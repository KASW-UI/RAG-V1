# P-23 · 对照探针的**顺序注入** ⇒ 读数差混进了「两侧调用起点差」⇒ **假差**（且对修复**完全不敏感**）

> **登记时间**：2026-11-03（users-user 域 · 收口 **DRIFT-USER-PARITY-006** 时暴露）
> **性质**：**验证方法学**的坑（对拍/活体探针的**注入对称性**）
> **发现者**：对称注入改造后的一次跨侧复跑

---

## 一、形态

对拍探针常见的一种写法是**顺序**注入：

```
发 A 侧的调用 → 等它返回 → 发 B 侧的调用 → 等它返回 → **这时才放行被冻结的依赖**（PG / Redis / 下游）
```

⇒ ⇒ **A 侧的调用比 B 侧早 ≈「一次客户端往返 + 一次取消等待」**（本例 ≈ 1 秒：两次 JVM 启动 + 各自的 1s 取消）
⇒ ⇒ **放行那一刻，两侧离各自「服务端预算到点」的距离不同**
⇒ ⇒ 而**被观察的结果（那条写落不落库 / 那个响应是什么）由「放行那一刻还剩多少预算」决定**
⇒ ⇒ **两侧读数必然不同** ⇒ ⇒ **读数差 = 注入时序，不是行为差异**。

🔴 **最要命的一点**：这类读数**对被测代码的修复完全不敏感**
⇒ ⇒ 修前修后读数**一样** ⇒ ⇒ **既证不了差异，也证不了修复** ⇒ ⇒ 探针在那段时间里是**假绿**。

## 二、判定式

1. **凡「时序敏感」的读数**（超时 / 取消 / 在途写 / 预算类判据）⇒ **注入必须对称**：
   - 两侧调用由**同一个客户端**发出（起点相差微秒级，而不是「两次进程启动」）；
   - 两侧的取消/超时在**同一个绝对时刻**发生；
   - **放行时刻相对「调用发出的时刻」定义**，而不是相对「脚本开始的时间」⇒ ⇒ 两侧**等距**。
2. **单点相等只是弱证据** ⇒ ⇒ **扫多个偏移**，比**翻转点**（结果从「有」变「无」的那个偏移）是否重合
   ⇒ ⇒ 翻转点 = 被测语义（预算语义）的**直接投影** ⇒ ⇒ 重合 ⇒ 语义等价。
3. **发现顺序注入时，先怀疑读数、再怀疑代码** ⇒ ⇒ **先跑一次「只变放行时刻」的机制实验**（本仓侧、零成本）
   ⇒ ⇒ 若行数随放行时刻翻转 ⇒ ⇒ **该读数不可用于行为判定**。
4. ⚠️ **别把「真差异数下降」当成「修好了」** —— 注入改成对称后真差异数下降，
   可能只是**假差被剔除** ⇒ ⇒ 台账里必须写清「哪几条是假差、依据是什么」。

## 三、实测代价（RAG-V1 · users-user 域 · PARITY-006）

- **旧读数**（顺序注入）：客户端 1s 取消一个写路径调用 ⇒ 两侧都回 `CANCELLED` ⇒ 放行 PG 后查库
  ⇒ **B = 0 行 · C = 1 行** ⇒ 曾判为「真差异」，并做过一次**代码级归因**
  （共享层 gRPC 拦截器缺 `onHalfClose` 里的 `DeadlineState.bindAbsoluteNanos(...)` ⇒ handler 线程无 deadline
  ⇒ injector 不注入 `setQueryTimeout` ⇒ 在途写不被取消）。
  ⇒ ⚠️ **归因本身是对的**（那个缺口真存在、也真补了）⇒ ⚠️ **但由此推出的「行为差异」不成立**。
- **机制实验**（本仓侧 · 只变「放行时刻」）：

  ```
  [RELEASE-TIMING] R1（cancel@1s · 放行@1.2s · 预算剩 ~0.8s）⇒ 行数=1 · handlerError=null · 客户端=StatusRuntimeException(CANCELLED) · 客户端耗时=1013ms
  [RELEASE-TIMING] R2（cancel@1s · 放行@2.6s · 预算已耗尽）⇒ 行数=0 · handlerError=StatusRuntimeException(DEADLINE_EXCEEDED) · 客户端=StatusRuntimeException(CANCELLED) · 客户端耗时=1004ms
  ```

  ⇒ ⇒ **客户端取消时刻相同 ⇒ 行数随「放行时刻」翻转** ⇒ ⇒ **「谁先取消」不决定行数**；
  ⇒ ⇒ **R1 的 `handlerError=null`** ⇒ ⇒ 服务端**没有**因客户端取消而停手（与 B 侧 `onCancel` 同款：只撤自己的超时调度器，不打断 handler）。
- **对称注入复跑**（两侧真进程 · 同一 JVM 发两侧 · 同一时刻取消 · 等距放行）：

  ```
  · 放行@+1200ms ⇒ B=1 · C=1
  · 放行@+1800ms ⇒ B=1 · C=1
  · 放行@+2400ms ⇒ B=0 · C=0
  · 放行@+3000ms ⇒ B=0 · C=0
  · 翻转点（1 行 → 0 行）：B 侧=2400 · C 侧=2400
  ✅ 两侧翻转点重合（=2400）⇒ 预算语义等价
  ```

  ⇒ ⇒ **逐点相同 + 翻转点重合** ⇒ ⇒ **两侧行为等价** ⇒ ⇒ **旧读数是假差**。
- **探针层变异**（拿掉那个绑定 ⇒ 复跑同一探针）：

  ```
  · 放行@+2400ms ⇒ B=0 · C=1
  · 放行@+3000ms ⇒ B=0 · C=1
  · 翻转点（1 行 → 0 行）：B 侧=2400 · C 侧=None
  ```

  ⇒ ⇒ **判据有牙齿**（C 不再跟随 B 翻转）⇒ ⇒ **该修复确实必要**；
  ⇒ ⇒ ⚠️ **同时证明旧探针是假绿**：变异态下 C 在**所有**偏移都读 1 ⇒ ⇒ 旧顺序注入读到的「C=1」**修前修后完全相同**。

## 四、附带的一条

**「改探针」本身是产出**：旧探针留下的**唯一价值**是「它报出来的差异是真的吗」这个问题本身
⇒ ⇒ 改完之后要**把旧读数与新读数并排留在台账里**（含机器输出逐字）⇒ ⇒ 否则复核人只会看到「新读数是绿的」，
不知道「旧的差异是被证伪了还是被藏起来了」。

## 五、同族

- 与 P-12「变异没变红 = 那条断言没覆盖到」同源：**读数恒定 ⇒ 判据没有牙齿**（此处更进一步：**恒定到连修复都测不出来**）。
- 与「场景有效性断言」（每条场景判据都要配一条「我测的是这个场景吗」）同源：
  **「两侧对称」是场景有效性的一部分** —— 对照实验的**对照项本身必须同形**。
