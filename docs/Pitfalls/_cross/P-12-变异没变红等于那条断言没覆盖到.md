# P-12 · 「变异没变红」＝「那条断言<b>没覆盖到</b>」—— 而不是「变异是安全的」

> **登记时间**：2026-11-02（批次 C · 修 **DRIFT-COMMON-V04**「HTTP 超时 503 + 断连 499 + worker 池」时暴露）
> **性质**：**验证方法学**的坑（AGENTS.md §3.3「变异测试是另一半」的那一半）
> **发现者**：批次 C 的第 3 次变异实测（把「探针断连 ⇒ 499」改成 500）

---

## 一、形态

§3.3 要求「引入新框架机制必须配一条**真正触发它**的测试」，并补一句「**变异测试是另一半**」——
即：把实现改坏 ⇒ 断言必须变红 ⇒ 才能证明这条断言**不是假绿**。

⇒ ⚠️ **实测发现**：变异改坏之后**断言没变红**，此时有**两种**解释：

| 解释 | 含义 | 处置 |
|---|---|---|
| (a) 「这个变异**不影响可观察行为**」 | 变异是**等价的** | ✅ 可以接受（但要能说清为什么等价） |
| (b) 「**这条断言根本没覆盖到那条分支**」 | 变异改的是**另一条分支** | 🔴 **必须补测试** |

⇒ ⇒ **默认应当先假设 (b)**，直到能证明是 (a)。

## 二、实测代价（RAG-V1 · 批次 C）

批次 C 给 `HttpMiddleware` 加了**三条拒绝路径**（超时 503 / 断连 499 / 池饱和裸 503），
并给每条写了断言。

第 3 次变异实测：把**两处** `writeTimeoutResponseQuietly(HTTP_CLIENT_CLOSED_REQUEST, …)`
改成 `SC_INTERNAL_SERVER_ERROR`（500）⇒ ⇒ **测试全绿**。

⇒ ⚠️ **绿** ⇒ 第一反应是「499 这条断言是假绿」⇒ 但读完代码才发现：
**被改的那两处**（探针判定断连分支 ＋ 容器线程被中断分支）
与**被测的那处**（业务线程抛 `ClientAbort` ⇒ panic 分支里的 `statusCode` 计算）**不是同一条路径**：

```java
// 被测的那条（panic 分支）—— statusCode 是运行时算出来的
int statusCode = clientCancelled ? HTTP_CLIENT_CLOSED_REQUEST : 500;
rec.writeTimeoutResponseQuietly(statusCode, httpReq);

// 被改的那两条 —— 直接写常量
rec.writeTimeoutResponseQuietly(HTTP_CLIENT_CLOSED_REQUEST, httpReq);
```

⇒ ⇒ **变异改的是「没被测到的那两条分支」** ⇒ ⇒ 绿是**应该的**（那两条分支本来就没覆盖）。

## 三、修法（把「没覆盖」变成「覆盖」）

给不可直接驱动的机制加**测试接缝**（**只在测试里注入，生产路径不变**）：

```java
/** 🔴 测试接缝：断连探针可注入。默认实现 = ClientDisconnectProbe::probe。 */
private final DisconnectProbe probe;

@FunctionalInterface
public interface DisconnectProbe {
    ClientDisconnectProbe.State probe(HttpServletRequest request, HttpServletResponse response);
}
```

⇒ 单测注入「恒返回 `DISCONNECTED`」的探针 ⇒ **探针断连分支被真正驱动** ⇒
再变异 ⇒ **变红** ✅ ⇒ ⇒ 这条分支**从此**被覆盖。

⚠️ **纪律**：接缝**只允许在测试里注入**，生产构造器**恒走真实现**；
且接缝必须在类 javadoc 里写明「**仅供单测**」（避免后来者把它当扩展点乱用）。

## 四、判定式（可复用）

1. ⇒ ⇒ **凡做变异实测 ⇒ 「没变红」当作「没覆盖」处理**（而不是「变异安全」）。
   ⇒ ⇒ 例外只有一个：**能说清为什么该变异与原实现等价**（例如改了日志文案、注释、局部变量名）。

2. ⇒ ⇒ **变异要「改在被测的那条分支上」** ⇒ ⇒ 改之前先确认：
   **被测断言驱动的是哪条分支**（逐行对照，别凭印象）。
   ⇒ ⚠️ **同名常量出现在多处时，「改全部」与「改被测的那处」是两回事**。

3. ⇒ ⇒ **分支驱不动时（依赖真容器 / 真网络 / 真 socket）⇒ 加测试接缝**，而不是「这条分支不测」。
   ⇒ ⇒ 接缝的形状 = **函数式接口 + 生产构造器固定真实现 + 包级构造器供测试注入**。

4. ⇒ ⇒ **补完接缝后必须再变异一次** ⇒ ⇒ 确认「这次变红了」⇒ ⇒ 才算补上。

5. ⇒ ⇒ **记进台账**：本仓的教训落点 = `docs/DRIFT/common/verification-common-2026-11-02.md`
   的批次 C 段（「其中一次变异最初没有变红 ⇒ 说明那条分支当时没被覆盖 ⇒ 补了探针接缝 ⇒ 再变异 ⇒ 变红」）。

## 五、同族

- 与「**『跑绿』≠『本来就绿』**」同源：那条讲的是「门禁绿不等于代码对」；
  本条讲的是「**变异没让门禁红 ⇒ 门禁压根没看那条分支**」。
- 与「**状态自报 ≠ 现状**」同源：两者都是「**声称覆盖了 ≠ 真覆盖了**」。
- 与「**零命中的读数 ⇒ 先证明命令本身成功**」同源：都是「**读数的解释方式**本身可能骗人」。
