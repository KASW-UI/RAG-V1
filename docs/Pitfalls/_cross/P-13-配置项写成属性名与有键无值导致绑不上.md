# P-13 · 「配置项写成了**属性名**」与「**有键无值**」⇒ 绑不上 ⇒ **进程起不来**

> **登记时间**：2026-11-02（`align/users-admin` 工作树 · 写 admin 域的真 Tomcat 契约测试时暴露）
> **性质**：**配置绑定**的坑（AGENTS.md §3.3.1「『配置里没写』≠『没开』」的**反面**：**『配置里写了』也可能**绑不上**）
> **发现者**：第一次让 admin 域**真起上下文**时（此前全仓**零** `@SpringBootTest` 上下文测试 ⇒ 任何「起不来」的缺陷都藏着）

---

## 一、形态

同一族的两条坑，**共同点是「绑定失败 ⇒ 启动失败」**，而**编译期完全看不出来**：

| # | 形态 | 表现 |
|---|---|---|
| **A** | **把「属性名」写在了「Map 的键」的位置** | `ConverterNotFoundException: No converter found capable of converting from type [String] to type [XxxProperties]` |
| **B** | **只留下键、不给值**（下面全是注释） | **同上**（值被读成**空串**） |

### 形态 A 的实例（devh gRPC 3.1.0）

```java
@ConfigurationProperties("grpc")
public class GrpcChannelsProperties {
    private final Map<String, GrpcChannelProperties> client = new HashMap<>();  // ← 键 = 通道名
}
```

⇒ `grpc.client.<X>` 的 `<X>` 是**通道名**，**不是属性名**
⇒ ⇒ 写 `grpc.client.negotiation-type: plaintext` ⇒ 被理解成「**名叫 `negotiation-type` 的通道**，其值是字符串 `plaintext`」
⇒ ⇒ 绑不成 `GrpcChannelProperties` ⇒ **启动失败**。

⇒ ⚠️ **正确写法**：给某个通道 ⇒ `grpc.client.<通道名>.negotiation-type`；
给**所有**通道设默认 ⇒ 全局通道的键是**字面量 `GLOBAL`** ⇒ `grpc.client.GLOBAL.negotiation-type`。

### 形态 B 的实例（同一个坑的第二层）

把形态 A 的那行**删掉**之后，剩下的只有：

```yaml
grpc:
  client:
    # ⚠️ negotiation-type 必须显式写 plaintext：…
    #    不写会静默变 TLS ——
```

⇒ ⚠️ **Spring 的 YAML loader 把「有键无值」读成 **空串**（不是 `null`）**
⇒ ⇒ `grpc.client` = `""` ⇒ 绑到 `Map<String, GrpcChannelProperties>` **同样失败**
⇒ ⇒ **启动失败**（报错里会写 `Property: grpc.client / Value: ""`）。

⇒ ⇒ **连「只有注释的键」都不能留** ⇒ 要么给真值，要么**整段删掉键**。

---

## 二、实测代价（RAG-V1 · admin 域）

- admin 域的 `application.yml` 里写了 `grpc.client.negotiation-type: plaintext`（**本域无 `@GrpcClient` bean，压根没有消费者**），
  ⇒ ⇒ **admin 应用根本起不来**。
- ⚠️ **为什么藏了这么久**：**全仓此前没有任何一个 `@SpringBootTest` 上下文测试** ⇒
  「起不来」这件事**没有任何一条测试能发现** ⇒ ⇒ 域内 58 个文件全绿（业务单测都绿）**也照样起不来**。

---

## 三、判定式（可复用）

1. ⇒ **凡要往 `@ConfigurationProperties` 的 `Map` 字段里塞值 ⇒ 先读那个类的字段声明**
   ⇒ ⇒ 键位是**子键名**（通道名 / bean 名），不是属性名。
2. ⇒ **凡在 yml 里「只留一个键 + 一堆注释」⇒ 先假定它会被读成空串** ⇒
   ⇒ 若该键的绑定目标是 `Map` / POJO ⇒ **要么给值，要么整段删**。
3. ⇒ **「起不来」的缺陷只有一个测试能发现 ⇒ 就是「真起一次上下文」**
   ⇒ ⇒ 域内**至少要有 1 个 `@SpringBootTest`**（哪怕只断言「上下文能起来 + 种子数据建出来了」）。
4. ⇒ **踩坑后不要只删掉那一行** ⇒ ⚠️ 形态 B 说明：**删掉值还不够，键本身也要删**。

---

## 四、修法（本仓落点）

- `service/users/admin/src/main/resources/application.yml` —— **整段删掉 `grpc.client:` 键**，只留注释块，
  并在注释里写清「将来加 `@GrpcClient("X")` 的正确写法」。
- `service/users/admin/src/test/java/com/rag/admin/AdminServiceApplicationTests.java` ——
  **真上下文启动测试**（真 Tomcat + 真 gRPC server + 真 PG + 真 Redis）⇒ 这道防线就是被本坑逼出来的。
- ⚠️ **同仓其它 7 个域的 yml 有同样的形状**（`grpc.client:` + 只有注释）⇒
  ⇒ **它们一旦要起上下文，会踩同一个坑** ⇒ 已在各域处理时逐条核对（本坑不修共享层，因为 `tools/` 与其它域不在本 lane 范围）。

## 五、同族

- 「**配置里没写** ≠ 没开」是 AGENTS.md §3.3.1 的纪律 ⇒⇒ **本条是它的反面：「配置里写了」也可能没生效（而是直接炸）**。
