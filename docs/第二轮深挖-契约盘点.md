### 1.3 `Event` 与 `TechnicalReceipt` 的字段（L1，逐字）

```go
type Event struct {
    EventID          string          `json:"event_id"`
    EventType        string          `json:"event_type"`
    SchemaVersion    int             `json:"schema_version"`
    Producer         string          `json:"producer"`
    AggregateID      string          `json:"aggregate_id"`
    AggregateVersion int64           `json:"aggregate_version"`
    OperationID      string          `json:"operation_id"`
    OccurredAt       string          `json:"occurred_at"`
    Payload          json.RawMessage `json:"payload"`
}

type TechnicalReceipt struct {
    EventID         string `json:"event_id"`
    Producer        string `json:"producer"`
    TechnicalStatus string `json:"technical_status"`
    ReceiptID       string `json:"receipt_id"`
    InputHash       string `json:"input_hash"`
    Offset          int64  `json:"offset"`
    ReceivedAt      string `json:"received_at"`
}
```

⚠️ **`Payload` 是 `json.RawMessage`** ⇒ 延迟反序列化 ⇒ 生产者域拥有 payload 语义，协议层只搬运。
⚠️ **`SchemaVersion` + `AggregateVersion` + `OperationID`** ⇒ 这是一套**事件溯源 + 幂等**协议，不是普通消息队列。

### 1.4 ⚠️ 最危险的一处：canonical JSON 哈希

```go
func CanonicalHash(raw []byte) (string, error)   // 用 github.com/cyberphone/json-canonicalization（RFC 8785 JCS）
```

⇒ **Spring 生态没有等价物。** Jackson 的 `MapperFeature.SORT_PROPERTIES_ALPHABETICALLY` **不等价** ——
JCS 还规定了数字规范化（`1.0` vs `1`）、字符串转义（`/` 不转义）、UTF-16 码元顺序等。

⇒ **指纹不一致 ⇒ 去重失效 + 回执校验失败 ⇒ L3 幂等性破。**
⇒ **落地**：新增 `common/communityfact/CanonicalHash.java`，并**接入 RFC 8785 库**（`com.github.erosb:everit-json-schema`? 不 —— 正确的是 `org.everit.json.schema`? 实际 JCS 实现见 §四 T-3）。
⇒ **这是本项目里"生态无等价物"的第 2 个缺口**（第 1 个是 CPU 降载）。

### 2.3 ⚠️ 缺陷 1：`like-rpc_action_total` 用了连字符

Go 源码：
```go
LikeActionCount = prometheus.NewCounterVec(prometheus.CounterOpts{
    Namespace: "",
    Subsystem: "like-rpc",          // ← 全仓唯一用连字符的
    Name:      "action_total",
```

⚠️ **Prometheus 指标名正则 `[a-zA-Z_:][a-zA-Z0-9_:]*` 不允许连字符** ⇒ 该指标**不会出现在 `/metrics` 里**。

⇒ **登记为已知缺陷**（`docs/Intentional_Deviations/` 或 `docs/Pitfalls/`），**不得"顺手修正"**。

### 2.4 ⚠️ 缺陷 2：`high_risk_action_logal` 拼写错误

Go 源码：`Name: "high_risk_action_logal"`（应为 `log` / `audit`）。

⇒ **决策：照抄，不修正。** 指标名是**监控看板的依赖项** ⇒ 改 spelling 会让既有看板断裂。

## 五、T-5 · 翻案：Go 的 task 域**有** `UserLikeCount`

第一轮深挖我按目录名盘点 `internal/model/`，得出「Go 侧 task 域无持久化实体」—— **错**。

**真相**：
```go
// service/task/rpc/internal/sink/like_sink.go
type UserLikeCount struct {
    LikeCount int64 `gorm:"column:like_count"`
}
func (UserLikeCount) TableName() string { return "user_like_count" }
```

⇒ Go 把它放在 **`internal/sink/`**（因为它由 like 事件 sink 维护），不在 `internal/model/`。
⇒ **RAG 的 `UserLikeCountEntity` 是正确的**，只是位置与 Go 不同（Go 在 sink 逻辑包内，本仓库归入 `rpc/domain/`，性质等价）。
⇒ 已写入该类的 javadoc。

> **这是"按目录名归类"的第二次翻车**（第一次是 `errmsg.go`）。⇒ 再次印证 §1.1 的纪律：
> **盘点要按导出符号，不能按目录。**

## 七、本轮的第二个教训：**"生态无等价物"清单要单列**

第一轮深挖发现 1 处（CPU 降载），本轮发现第 2 处（canonical JSON / RFC 8785 JCS）。

⇒ 两处都是**必须自研且必须逐字对拍**的点，且都**不是业务语义**（一个在熔断、一个在幂等指纹）。
⇒ 建议在 `docs/L3-降级清单.md` 旁边新增一档：**「生态无等价物清单」**（待办）。

| # | 能力 | 生态现状 | 替代方案 | 风险 |
|---|---|---|---|---|
| G-1 | CPU 降载（`CpuThreshold` 900‰） | resilience4j 无等价 | 自研 `CpuThresholdHealthIndicator` | L3 |
| **G-2** | **canonical JSON 哈希（RFC 8785 JCS）** | Jackson 不等价 | **需引 JCS 库或自研** | L3（幂等） |
| G-3 | `go-zero` 的 `rest.Middleware` 链顺序 | Spring `Filter`/`Interceptor` 链可表达但语义不同 | 显式链式配置 | L3 |
| G-4 | `logx` 的 `call_chain` 字段 | SLF4J 无等价 | 自研 `Logger implements slf4j.Logger` | 已规划 |

> ⇒ RAG-V1 的「一域一 app」形态**无法容纳它们** ⇒ 需要重新审视 D1（api/rpc 合并）在这类域上的适用性。
>
> 🟢 **2026-10-25 已解** —— 上面的判断**过头了**：Go 侧实际只有 `comment`/`favorite`/`like` 三域的
> `fact-dispatch` / `fact-authority`（+ favorite 的 `fact-legacy-preflight`）是业务进程，
> 且**都不注册任何对外服务** ⇒ RAG 的组件级对照已判定 Go 的"独立进程"是**架构意图而非技术约束**
> （`docs/FileTree/like/rpc.md:84-97`）⇒ **D1 不设例外**。
> 另：`task/rpc/internal/Init/*` **不是独立进程**（是 `task/rpc/task.go:31-35` 的进程内 goroutine）；
> `hot/test/cmd/*` 是压测工具；`knowledge/cmd/*` 范围外。
> ⇒ 落地：三域各补 `wiring/<域>FactDispatchScheduler` + `<域>AuthorityEndpointConfig`；
> 三个遗留子项（`-once` 模式 / `fact-authority` 端口 / `fact-legacy-preflight` 入口）⇒ [`决策记录.md`](决策记录.md) **P6**。
