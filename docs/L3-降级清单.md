# L3 降级清单

> **本文档记录"完全 Spring 化"过程中，被有意放弃的 L3（影响可观察行为的技术语义）。**
> **这些是决策，不是缺陷** —— 不得反向"修回"旧行为；若认为某条必须保真，走 [`决策记录.md`](决策记录.md) 的 P1–P5 重新拍板。

---

## 〇、什么是 L3

| 层 | 内容 | 本仓库的处理 |
|---|---|---|
| **L1** 外部契约 | HTTP 路由 / 方法 / 出入参、gRPC 方法与 proto、错误码取值、状态码 | **全部保留**，一个字节都不改 |
| **L2** 业务语义 | 业务规则、状态转换、鉴权结果、读写含义、副作用与触发条件 | **全部保留** |
| **L3** 技术语义 | 事务边界、错误传播、超时重试降级、幂等、并发控制、序列化、资源生命周期、消息投递 | **保 6 降 4** |
| **L4** 实现机制 | 依赖注入、配置绑定、拦截器、注册与生命周期、文件划分、样板代码 | **全面重选** |

> **降级的判定标准**：降级项**全部落在框架内部行为**上，**没有一项落在业务语义上**。
> 业务语义降级 = 业务行为变了 = 必须重新拍板，不能由"框架更地道"顺带发生。

## 一、降级项（4 项）

### D-01 · 请求体必填校验的错误文案

| 项 | 内容 |
|---|---|
| **Go / RAG 现状** | go-zero `httpx.Parse` 走 `core/mapping`，必填缺失时返回 `400  field "username" is not set`（含字段名）。 |
| **完全 Spring 化后** | Bean Validation（`@NotNull` / `@NotBlank`）⇒ 错误文案由 Hibernate Validator 决定，与 go-zero 不同。 |
| **为什么降级** | 逐字复刻需自定义 `ConstraintValidator` + 维护 go-zero 的文案规则，**成本高于收益**。 |
| **影响面** | 仅错误**文案**。状态码（400）、错误**结构**（text/plain vs JSON）由 `GoStyleRouterErrorResponses` 独立保证，**不受影响**。 |
| **关联决策** | [P1](决策记录.md#p1--错误文案保真度) |
| **验收方式** | 双侧对拍时**忽略 error body 的文本**，只断言 status code + content-type + 错误结构。⇒ **对拍脚本必须显式排除此项，否则会全红。** |

---

### D-02 · 熔断（circuit breaker）的内部策略

| 项 | 内容 |
|---|---|
| **Go / RAG 现状** | go-zero `rest` 内置 `Middlewares.Breaker`（`rest/config.go:15`），默认开启。失败判定窗口、half-open 探测策略、错误率阈值由 go-zero 定义。 |
| **完全 Spring 化后** | resilience4j `CircuitBreaker`。**默认参数与 go-zero 不等价**（滑动窗口大小、最小请求数、wait duration、异常类型判定都不同）。 |
| **为什么降级** | resilience4j 无 go-zero 语义等价配置；逐项对拍需构造大量故障注入场景。 |
| **影响面** | ⚠️ **这是 4 项里影响面最宽的** —— 熔断行为直接影响"什么请求会被拒"。属**可用性语义**，仍属 L3 而非 L2（不改变业务规则，只改变故障时的拒绝策略）。 |
| **关联决策** | [P2](决策记录.md#p2--熔断语义) |
| **验收方式** | 必须做**故障注入对拍**（人为制造下游失败 ⇒ 比对"第 N 次请求后开始拒绝"）。⇒ **未做对拍前，不得把 P2 判为 ③ 完成。** |

---

### D-03 · 链路追踪（span）的名称与属性

| 项 | 内容 |
|---|---|
| **Go / RAG 现状** | go-zero `zrpc` 提供的 Trace / Recover / Stat / Prometheus / Breaker / Shedding 中间件链，`observability` 包定义 span 名称与属性；`sea.slow` 等标记是业务约定。 |
| **完全 Spring 化后** | Micrometer Observation + OpenTelemetry bridge。span 名称、属性 key、慢调用标记的生成方式不同。 |
| **为什么降级** | Micrometer 的观察模型与 go-zero 的中间件链不是一对一映射。 |
| **影响面** | 观测数据（trace / metrics 的 label）—— **不影响业务响应**。但 `sea.slow` 这类**业务定义的标记**必须保留（见下）。 |
| **保留项（不降级）** | ① 指标名与标签（如 `message_api_request_total{route,result}`）是**业务定义**，逐字保留；② 慢调用阈值与标记语义保留。 |
| **验收方式** | 指标名 / label 的逐条比对（`tools/difftest/` 扩展）；trace 属性可接受差异但需在文档登记。 |

---

### D-04 · CPU 降载（adaptive shedding）的实现路径

| 项 | 内容 |
|---|---|
| **Go / RAG 现状** | go-zero `rest` 内置 `CpuThreshold`（`rest/config.go:56`，默认 900‰ = 90% CPU），读整机 CPU（Linux `/proc/stat`）。 |
| **完全 Spring 化后** | resilience4j **无等价能力** ⇒ 保留 1 个自研 `CpuThresholdHealthIndicator`（读 CPU + 暴露健康状态），由 Spring Boot Actuator 的健康检查与一个 Filter 消费。 |
| **为什么降级** | 生态缺口，**不是选择** —— 不自研就没有这个能力。 |
| **影响面** | 超阈值时的**拒绝响应形状**（裸状态码 + 空 body + 无 Content-Type）必须保留。 |
| **关联决策** | 与 [P2](决策记录.md#p2--熔断语义) 同批落地。 |
| **验收方式** | 人为压高 CPU ⇒ 比对拒绝行为与响应形状。 |

## 二、保留项（6 项，明确不降级）

> 这些是 L3，但**有对应的 Spring/Jackson 机制或语义等价物**，必须逐条保住。

| # | L3 语义 | 承载方式 | 注意 |
|---|---|---|---|
| K-01 | 请求体类型强转判定（数字/布尔不进 String 字段、浮点不进整数字段） | **Jackson 原生 `CoercionConfig`**（`CoercionAction.Fail` / `ACCEPT_FLOAT_AS_INT` off） | RAG 早已在用（`GoStyleCoercion`），**这不是自研** —— 已归位到 `common/web/` |
| K-02 | "何时才读请求体"判据（`ContentLength > 0` 且 Content-Type **字面**含 `application/json`） | 自定义 `HttpMessageConverter.canRead` | ⚠️ **字面子串匹配**，不是媒体类型兼容判定 ⇒ `application/vnd.api+json` 在 Go 侧**不**匹配 ⇒ body 被丢弃。这条必须逐字复刻 |
| K-03 | 超时取消在途 IO（`context.WithTimeout` 的 ctx-aware 取消） | `DeadlineState` + `setQueryTimeout`（pgjdbc CancelRequest） | ⚠️ Java 的 `Future.cancel(true)` 对阻塞 IO **无效** ⇒ 必须走服务端取消语义。RAG 已实测坐实 |
| K-04 | 日志输出格式（含 `call_chain` 字段等） | **实现 SLF4J `Logger` 的适配器** | 格式是行为契约；接入 SLF4J 生态不改变输出 |
| K-05 | 事务边界 / 行级悲观锁 / 幂等键 / 游标编码 | 逐条保留 | 这些是业务语义，不是框架机制 |
| K-06 | `ApiResponse` 信封形状（`{code,msg,data}`） | `common/contract/ApiResponse` | ⚠️ **不可用 `ProblemDetail` 替换** —— 客户端按此解析，属 L1。`ProblemDetail` 只能用于内部异常表达 |

## 三、变更登记规则

| 规则 | 说明 |
|---|---|
| **降级项不得反向修回** | 一旦拍板降级，后续实现**不得**"顺手"恢复旧文案 / 旧策略。要恢复 ⇒ 走 P1–P5 重新拍板并更新本文档。 |
| **降级项不得静默扩大** | 新增降级必须写进本文档，**不能只写进代码注释**。 |
| **对拍脚本必须显式排除降级项** | 否则双侧对拍会因文案差异全红 ⇒ 红了会被误判为"回归" ⇒ 触发"修回旧行为" ⇒ **降级被静默撤销**。⚠️ 这是最容易出问题的一环。 |
| **降级项与有意偏离分开记** | 降级 = 主动放弃 L3；有意偏离 = 两侧确实不同且已签字。本文档属前者，`docs/Intentional_Deviations/` 属后者。 |
