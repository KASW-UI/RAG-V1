## `gen-file-tree.py` 的约定

- **不手写文件树文档** —— 文档由脚本从文件系统生成 ⇒ 不会与代码漂。
- **输出布局 = 源树路径的镜像**：去掉 `service/` 前缀，模块路径末段换 `.md`
  （`service/users/user` → `docs/File_Tree/users/user.md`；`service/article` → `docs/File_Tree/article.md`）
  ⇒ `users/` 保留 `user/`·`admin/` 两级。
- ⚠️ **打平后的模块清单（2026-10-26）**：每域**一个** jar 模块（`service/<域>/`）——
  各域的 `*-contract` 模块已并入域模块（错误契约 + 事件 DTO 在 `com.rag.<域>.contract` 包），
  `.proto` 契约集中到**根级 `proto/` 模块**（pb 类包名 `com.rag.proto.<域>`）⇒ 叶子模块 22 → **13**。
  `service/users/` 仍是聚合结构（真有两个子域）⇒ `user` / `admin` 各自一个 jar 模块。
- ⚠️ **物理目录 ≠ artifactId**：目录叫 `user` / `admin` / `article`，artifactId 仍是 `user-service` / `admin-service` / `article-service`（Maven reactor 内须唯一）⇒ 文档里两者**分列两行**，**不要用目录名反推 artifactId**。
- **排除构建产物**：`target/` 不进文件树（否则编译一次就会混入 `.class`）。
- **幂等**：每次运行先清掉不再产出的陈旧 `.md` 与空目录（含历史遗留的拼写错误目录），再重新生成 ⇒ 连跑两次结果一致。
- 每个文件树上标注了该文件的**首行职责**（从 javadoc 抽取）。
- 每个模块额外带一段 **「特殊约定（L1 契约 · 勿凭直觉改）」** —— 这部分**手写**在脚本的 `SPECIAL` 字典里，改动时需同步。

## `check-mapping-coverage.py` 的约定

- **域路径表 = 域的聚合根**：RAG-V1 侧写 `service/<域>`（打平后每域一个 jar 模块，域内 `contract/` 包仍落在该根之下 ⇒ C 列分母不因打平而变）· B 侧写 `service/<域>`（B 侧 api/rpc 分离，两者的域聚合根同名）。
- ⚠️ **路径不存在即报红**：目录改名 / 模块被并掉后，路径表若没跟着改，会静悄悄走 `0 个文件 ⇒ 100% 覆盖` 的**假绿** ⇒ 脚本先断言路径存在，不存在直接 EXIT=1。
- ⚠️ **根级 `proto/` 模块不在本表**：它只有 `.proto`（无手写 Java），pb 类生成到 `target/` 被过滤 ⇒ proto 契约对照由 `difftest/check-proto-static.sh` 负责。
- 📌 **D16（2026-11-02）**：映射表由**三方列**改为**两方列**（原第三列已物理删除）⇒ A 列相关判据全部移除 ⇒ **B 列从参考列升为主判据**（并新增**按域**的 B 列覆盖率）。

### B 列守卫（第 ⑤ 重校验）的约定

> **背景**（2026-10-26 · D16 后口径不变）：C 列长期有机器守卫，**B 列一直没有** ——
> 而 §1.0c 已把 **B↔C 对应定为「逐类抄写路线图」** ⇒ B 列漏一个类 = 抄写时漏一个类。
> 2026-10-26 补上**双向对账**。

| 判据 | 方向 | 红了说明 |
|---|---|---|
| **B1 正向** | B 列写下的**具体类名** → RAG 磁盘 | 文档引用了 RAG 侧**不存在**的类（RAG 改名/删除后文档没跟上）|
| **B2 反向** | RAG 侧每个**业务** `.java` → B 列 | RAG 侧有类**没进 B 列** ⇒ 抄写路线图会漏掉它 |

- ⚠️ **只扫 B 列单元格，不扫全文** —— 全文里的 `.java` 也包含 C 列的类名，拿全文当 B 列会把「C 侧有、RAG 侧没有」的类误报成「B 列引用了不存在的类」。
- ⚠️ **B 列有三种写法，守卫必须全认**：**精确类名**（`Xxx.java`）· **通配**（`Message<Case>Service.java`）· **目录形态**（`like-rpc/…/mapper/`，**≥2 段**才收 —— 单段目录 token 会把全仓吞掉）。
- 🔴 **目录 token = B 侧文件路径的「分段前缀」**（`service/comment/comment-api` ⇒ 该模块下全部 `.java`）。
  ⚠️ **旧实现把「包名」与「类名」相比**（`dp[-1] == pkg`，而 `pkg` 取的是类名）⇒ **目录 token 永远不命中**
  ⇒ 凡靠目录 token 覆盖的类**一律被误报成未覆盖**（实测 `article` 域 74/83，而该域文档里明明写了 `service/article/article-api`）。
  ⇒ **D16（2026-11-02）改为前缀语义**；实测**只有 `article` 一域的数字变化（74 → 83）**，其余 9 域**逐字不变** ⇒ 这是修 bug，不是放松判据。
  ⇒ 连带效应：`B_COLUMN_WHITELIST` 的 3 条**因此失效并被移除**（它们其实早已被目录 token 覆盖）。
- ⚠️ **RAG 的 `tools/`（语义探针 / 对拍 runner）不是业务代码** ⇒ 不计入 B2 分母。
- 📌 **白名单**（`B_COLUMN_WHITELIST`）= 登记在案的例外，**每条必须写原因 + 核对日期**；脚本会报「已失效条目」⇒ **防白名单腐化**。
- ✅ **负向测试已做**（2026-10-26）：① 从白名单删一条 ⇒ B2 报红 ② B 列写一个不存在的类 ⇒ B1 报红 ③ 白名单塞一个已被覆盖的类 ⇒ 报「条目已失效」⇒ **不是不会失败的假守卫**。

### 第 ⑥ 重校验：指代消解后可判定性

> **要守的不是「有没有『同上』」，而是「消解后每行是不是都读得出」。**
>
> 「同上」是**确定性指代** —— B / C 各自独立**向上**取最近一个非「同上」的值，零歧义 ⇒ 机器完全能重建。

| 子判据 | 红了说明 |
|---|---|
| **⑥-a 孤立指代** | 「同上」向上找不到锚点 ⇒ **指代链断了**（真缺陷） |
| **⑥-b 未登记** | 消解后仍读不出「某个 `.java` 的落点」的行，**必须**登记在 `NON_FILE_LEVEL` ⇒ 未登记即报红 |
| **⑥-c 登记失效** | 已登记的行后来变得可判定 ⇒ 报「登记已失效，请删除」⇒ **防登记腐化** |

- ⚠️ **锚点规则**：只有「具体路径」或「明确否定」能当锚点 —— **纯描述文字不是锚点**（「同上」指的是上面那个**具体路径**，不是上面那段描述）。
- ⚠️ **消解按文档内顺序** —— 指代是「向上指」，跨文档不成立 ⇒ 换文档即重置。
- 📌 **`NON_FILE_LEVEL` 登记表**：键 = `(文档相对路径, B 列归一化文本[:60])` ⇒ **D16 后用 B 列（RAG 侧）做键**（A 列已物理删除）⇒ ⚠️ B 列会随实现推进变化 ⇒ 键**不再稳定** ⇒ 登记条目须定期复核。
- ✅ **负向测试已做**（2026-10-26）：① 主表首行写「同上」⇒ 报「孤立指代」② 某行 C 列改成纯描述 ⇒ 报「未登记」③ 已登记的行改得可判定 ⇒ 报「登记已失效」⇒ 三条全红、恢复后回绿。
  ⚠️ **负向测试抓到一个真 bug**：孤立指代时 `rb = last_b`（`None`）⇒ `_has_path(None)` 抛 `TypeError` ⇒ **整个脚本崩溃**（不是「没检测到」，是直接挂）⇒ 已修（置空 + 单独报）。

### 第 ⑦ 重校验：主表行形状

> **主表行的列数必须为 4**（`B | C | 映射类型 | 备注`）—— 单元格里的 `|` 没转义会被 markdown 当成列分隔符。

⚠️ **为什么必须报红而不是静默跳过**：
① **渲染错乱**（表格多出 1 列）；② **守卫按 `cells[0]` 取 B 列** ⇒ 该行的 B 列内容**静默丢失**
⇒ 正是 P-08「没人复算的证据 = 字节层面和愿望一样」的同病。

- 📌 **主表的识别按「表头第 3 格」**（`cells[2]` 是「映射类型」）⇒ `| 映射类型 | 条数 | 占比 | 说明 |`（统计表）**不算主表**。
- ⚠️ **切分要认转义** —— 直接 `ln.split("|")` 会把**已正确转义**的 `\|` 也切开 ⇒ 一行被误判成 6/7 列 ⇒ **文档本来就对、解析器不对**（实测 `like/like.md:136` 的雪花游标 `(unixMilli<<22)\|(nodeId<<12)\|seq` 就是这种）⇒ 故用 `_split_row()`。
- ✅ **负向测试已做**：在主表行 B 列塞入未转义的 `||` ⇒ 报「主表行有 5 列（应为 4）」EXIT=1；恢复后回绿。

### 第 ⑧ 重校验：`_INDEX.md` 合计行对账

- ⚠️ **合计行此前是唯一没人核对的自报数** —— `parse_index_table` 只对账**各域**的 4 项（行数 / C 覆盖 / **B 覆盖** / 映射行），**合计行不在其中** ⇒ 实测发现它长期与真实值差 1 而无人发现。
- ⇒ 与 P-08 同病（没人复算的数 = 字节层面和愿望一样）⇒ 补上：合计行的「行数」「映射行」与实测对账，漂了即报。
- ✅ **负向测试已做**：合计行 5,791 → 5,999 ⇒ 报「合计行的「行数」自报 5999 ≠ 实测 5791」EXIT=1；恢复后回绿。

## `difftest/follow/` 的约定（E-4 双侧活体对拍 · 2026-11-02）

> 完整设计、HTTP 21 条 ＋ gRPC wire 13 条 ＋ 场景轮 6 类（＋ 过渡窗口分层采样）的用例清单、35 条踩坑 ⇒ [`difftest/follow/README.md`](difftest/follow/README.md)。

### 目录名必须与派发器的约定一致

派发器 `difftest/run-parity.sh` 按 **`<域>/run.sh`** 找探针 ⇒ 目录必须叫 **`follow/`**。
⚠️ 本轮踩过：目录叫 `follow-parity/` ⇒ **派发入口永远报「没有登记探针目录」** ⇒ 文档写的入口其实**从没被跑过**（前几轮都是直接调 `run.sh`）⇒ **「登记了入口」≠「入口通」**。

### 三方判定（不是「两侧一致」）

探针判的是 **C 侧 == B 侧 == `expected.txt`（冻结的 Go 真源字节）** 三方相等。
- `expected.txt` **参与判定**（不是摆设）⇒ 变异 M2 专门盯这一条。
- ⚠️ **Go 侧不活体**（本机无 `Sea-etcd` 容器，Go 真源走 etcd 服务发现）⇒ 第三方锚用 B 侧 2026-10-29 录下的冻结字节。
- ⚠️ **双边锚的用例要单列**（如 `blacklist`）⇒ **不得**计入「三方一致」。
- ⚠️ **gRPC wire 层只有双边锚**（Go 真源的 wire 字节未冻结）⇒ 读作「**双侧一致**」。

### 场景轮（§九 的 11 类场景 · 双侧）

- 场景轮**会改库** ⇒ 必须排在 HTTP 矩阵与 wire 层**之后**。
- ⚠️ **判据按「业务码」而非「HTTP 状态码」**（本域业务失败恒 HTTP 200 + 业务信封）。
- ⚠️ **空洞判据必须显式排除**：target 不存在 ⇒ 两侧都在 5101 短路 ⇒ 「两侧一致」只证明了「两边都 5101」⇒ 判据要**钉死码值**（超时 = 1015 · 回滚 = 5008 · 并发 = {200}）。
- ⚠️ **故障层的读数可能非确定**（B 侧 gRPC 层在超时场景实测采样到两个不同的码）⇒ **只把确定的层当契约判据**，非确定的层降级为**观察项**（照样打印，不参与 EXIT 码）。

### 域隔离与只读

- 探针是**域私有**（`tools/` 不是业务代码 ⇒ 不计入 `check-mapping-coverage.py` 的 B2 分母）。
- **B 侧只读**：只在 B 仓跑 `mvn package`（产物落 `target/`，`.gitignore` 排除）⇒ 探针第 2 步**断言 B 仓 `git status` 干净**，否则 `die`（EXIT=2）。

### 必须配变异验证（AGENTS.md §3.3.3）

- 每个探针必须配 `mutate-parity.sh`：**M1** 打 C 侧字节 · **M2** 打冻结期望值 · **M3** 打两侧各自的库 · **M4** 打失败路径（不许读残留 body）· **M5** 复现 FAILING-010（证明 M4 的红来自守卫）。
- ⚠️ **变异必须针对被测形态设计，不能照抄别的形态的变异** —— 实测：B 侧的 M1（「删掉 `@JsonPropertyOrder`」）在 **class** 上能转红，在 **record** 上**转不了红**（record 默认按构造参数序输出 ⇒ 删注解字节不变）⇒ 本仓 M1 已改成「把注解**改成反序**」。

### 运行期纪律（踩过的坑，别再踩）

- ⚠️ **不要在探针运行期间编辑它自己或 `run.sh`** —— bash 按**字节偏移**增量读脚本 ⇒ 文件长度一变就错位 ⇒ 会把注释行当命令执行并重跑某一段。
- ⚠️ **worktree 内跑仓内脚本前先确认它看的是哪棵树**（本仓 `gen-file-tree.py` / `check-mapping-coverage.py` 的 `ROOT` 硬编码主工作区）。
- ⚠️ **Nacos 手工注册的实例要保活**（ephemeral 靠心跳，curl 注册没人发心跳 ⇒ ~15s 后被摘掉 ⇒ 表现为「服务名在、hosts 为空」）。
- ⚠️ **Docker Desktop(macOS) 的宿主不可达容器 IP** ⇒ 探针自己注册 `127.0.0.1` 形态的实例。
